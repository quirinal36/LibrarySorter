# 서가 렌즈 · Library Detector

카메라에서 청구기호 라벨을 자동으로 찾아 상대 배열을 검사합니다. 격자·열 수·정답 목록은 사용하지 않습니다.

## Jetson 서버 사진 검사 (기본 모드)

서버 구현은 루트의 `server/`로 분리했습니다. 루트에서 `python -m server.app`으로
실행합니다. 설치·HTTPS·접속 코드·API 안내는 [서버 안내](../server/README.md)를 참고하세요.
스마트폰은 고해상도 JPEG를 서버에 보내고 반환된 라벨 좌표와 판정을 촬영 사진 위에
표시합니다. 서버 사진 검사는 기기에서 OCR/MediaPipe를 내려받거나 실행하지 않습니다.
사진은 Jetson에서 파일 저장 없이 처리하고 Gadia에는 OCR 텍스트만 전달합니다.
접속 코드는 페이지 메모리에서만 사용하며 새로고침하면 다시 입력합니다.

아래 상세 OCR 설명은 선택 가능한 **기존 기기 OCR 모드**에 해당합니다.

## 동작

1. 4K 후면 카메라를 우선 요청합니다. 지원 기기에서는 `ImageCapture.takePhoto()`로 원본 사진을 촬영하고, 미지원 기기는 카메라 실제 해상도의 프레임을 사용합니다. 사진은 최대 긴 변 6000px·1800만 픽셀 이내에서 분석하며 입력/분석 해상도를 표시합니다.
2. 겹치는 6개 구역으로 나누어 최대 3배 확대·그레이스케일·대비 보정 후 한글·영문 OCR을 수행합니다. 구역 경계에서 중복된 글자를 합치고 원본 좌표로 복원합니다. 분류번호만 읽힌 영역도 라벨 후보로 재검사합니다.
3. OCR 단어 좌표에서 분류번호, 도서기호, 권차를 묶어 라벨 박스를 만들고 라벨별로 원본을 확대해 재인식합니다. 두 결과가 명확하게 충돌하면 신뢰도를 낮춰 보류합니다. MediaPipe는 라벨이 속한 책 영역을 보조적으로 연결합니다.
4. 비슷한 높이의 라벨을 행으로 묶고 왼쪽부터 읽습니다. 다음 행은 위에서 아래로 진행합니다.
5. OCR 문자열과 위치 순서를 Gadia의 `plexus/gpt-6-astra`에 보내 배열 규칙으로 판단합니다. 사진과 정답 데이터는 보내지 않습니다.
6. 촬영 프레임을 고정하고 청구기호 부분에 빨강(배열 이상), 노랑(보류), 초록(관찰 순서에 부합) 박스를 표시합니다.

Gadia 이미지 입력은 실제 호출에서 거부되어 텍스트 입력만 사용합니다. 기존 AI에 규칙을 전달하는 방식이며 별도 미세학습 모델은 아닙니다. 키 없이 ‘규칙 비교만’을 선택하면 OCR과 역순 쌍 확인을 로컬에서 실행할 수 있습니다.

## 실행

프로젝트 루트에서 실행합니다. Python 3.10 이상이 필요합니다.

```powershell
python LibraryDetector/server.py
```

주소: `http://localhost:8000/LibraryDetector/`

프로세스 환경변수 → `LibraryDetector/.env` → 루트 `.env` 순으로 설정을 읽습니다. `GADIA_API_KEY`는 서버에만 보관하며, `GADIA_MODEL` 기본값은 `plexus/gpt-6-astra`입니다.

스마트폰 카메라는 HTTPS가 필요합니다. LAN HTTP 주소만으로는 카메라가 열리지 않습니다. 인증된 HTTPS 프록시를 사용하는 경우 `DETECTOR_ALLOWED_HOSTS`에 도메인을 설정하고 원래 Host 헤더를 전달하세요. 개발 서버를 인증 없이 인터넷에 공개하지 마세요.

## 사용

카메라를 켜고 책 아래쪽의 청구기호가 크게 보이도록 정면에서 촬영한 뒤 검사하세요. 칸 수나 영역 지정은 필요하지 않습니다. 사진 파일도 사용할 수 있습니다. 자동 반복은 각 검사 완료 후 3.5초 뒤 다시 촬영하며, AI 모드에서는 요청 비용이 반복 발생합니다.

카메라 선택 메뉴에서 기본 후면 렌즈를 선택할 수 있습니다. 지원 기기는 연속 초점·노출을 적용하고 확대 슬라이더를 표시합니다. 브라우저가 센서 최대 해상도나 렌즈 종류를 보장하지 않으므로 화면의 실제 해상도를 확인하세요. 20권이 작게 찍히면 5~10권씩 가까이 찍는 편이 좋습니다. 확대 처리가 흔들림·반사로 사라진 글자 정보를 복구하지는 못합니다. iPhone 등에서 사진 API가 없으면 기본 카메라로 고해상도 촬영한 뒤 사진 불러오기를 이용할 수 있습니다.

분류번호 숫자순 → 한글 우선 도서기호 → 권차 숫자순을 적용합니다. 도서기호 숫자부는 이 프로토타입에서 소수식(`한17 < 한2`)으로 비교합니다. 기관별 규칙이 다르면 `recognition.mjs`와 서버의 `RULES`를 함께 조정해야 합니다.

인식하지 못한 라벨은 박스가 생기지 않을 수 있습니다. 현재 지원하는 기본 형식은 3자리 분류번호(선택적 소수), 한글/영문 도서기호와 숫자, 선택적 `v.N` 권차입니다. 회전된 책등, 작은 글씨, 심한 원근, 비슷한 높이의 여러 줄은 오인식·그룹화 오류가 생길 수 있습니다. 실제 카메라 정확도는 아직 측정하지 않았습니다. 초록 박스는 전체 책장이 정상임을 보장하지 않습니다.

단순 역순 쌍만으로 어느 책을 옮겼는지 알 수 없는 경우는 보류합니다. 같은 청구기호의 복본이나 다른 칸에 있어야 하지만 현재 순서는 맞는 책은 정답 목록 없이 특정할 수 없습니다.

## 테스트

```powershell
node --test LibraryDetector/tests/*.test.mjs
python -m unittest discover -s LibraryDetector/tests -p 'test_*.py'
```

합성 OCR 좌표·모델 어댑터·HTTP 검증이며 실기기 인식 평가를 대체하지 않습니다.

실제 Tesseract.js 6.0.1 엔진 검증: 저대비 16px 한글 라벨 20개 합성 이미지에서 기존 방식의 정확·신뢰도 통과 라벨 1개, 개선 방식 14개를 확인했습니다. 사용자 첨부 사진을 대상으로 한 측정은 아닙니다. 재현 스크립트는 `tests/verify-ocr.mjs`이며, 별도 임시 폴더에 `tesseract.js@6.0.1`, `@napi-rs/canvas`를 설치하고 그 폴더를 `OCR_VERIFY_ROOT`로 지정합니다. Windows 맑은 고딕을 사용합니다.
